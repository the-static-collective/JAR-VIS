## A new deterministic operator

The pure `src/boundary-inhabitation.mjs` compiler accepts an exact typed resource-problem fixture and systematically inhabits **four positions per missing resource**:

1. **Need-holder:** What property is actually necessary?
2. **Resource:** Where might the thing exist unused?
3. **Possible custodian:** Why might an owner voluntarily share, and what would make it reasonable?
4. **Crossing:** What are the permissions, physical conditions, custody/return obligations?

It records distinct transfer modes (permanent transfer vs temporary loan), verification gates, the smallest reversible first question, and an explicit PROPOSE_ONLY status. It never asserts a donor exists, a loan is agreed, a part fits, a repair succeeded or an external action was authorized. It never calls a real person.

Identical input produces a hash-stable plan. Changing one boundary relationship changes the plan deterministically.

## Technical and legal integrity gates

A programming interface can support diagnostics without supporting full module flashing. No salvaged module is presumed compatible. Before connecting hardware, get an exact donor/target hardware match, appropriate proprietary software/license and firmware provenance, vehicle-specific wiring/communication requirements and safe power procedure checked by a qualified person. Never offer bypasses for emission systems, immobilizers, or provenance.

**Measure success using actual witnessed transitions, not attractive pages:** label received → exact cross-reference confirmed/refused → willing donor/lender terms agreed → transfer/loan documented → mechanic confirms safe repair or unresolved blocker. No such outcome is yet claimed.

**Law:** UNOWNED ≠ UNUSED · RESEMBLANCE ≠ COMPATIBILITY · REQUEST ≠ CONSENT · LOAN ≠ DONATION · PROPOSAL ≠ REPAIR.
