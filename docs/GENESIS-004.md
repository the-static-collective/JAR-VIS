# GENESIS 004 — HOUSE PARTY / The Card That Made It Home

**Status:** TWO separate proof surfaces. The interactive demonstration is executable and fixture-only. A cold verification adapter exists for authentic historical STACK² 029 evidence, but no native OpenManus or ELF process is launched by the JAR;VIS workbench.

## Architecture

```text
JAR;VIS: observe need → propose bounded work → return artifact and restrictions
  LOADOUT: responsible for constituting effect scopes before a real provider launch
    OpenManus: potential bounded work engine (not invoked in fixture)
      ELF: an independently identified, mortal occurrence with owner-native receipts
        JAR;VIS: receive attributable artifact → independent check → HOLD human review
```

**First runnable specimen:** fictional Waseca Garden needs 12 produce boxes; synthetic grower offers 20. The JAR;VIS browser has a **House Party** panel that invokes `POST /api/house-party` on localhost after anti-CSRF verification. It generates a Table & Road Markdown card, creates separate *fixture occurrence labels* for drafter and checker, verifies content and source coherence using a different deterministic checking function, journals result, and displays it for inspection.

Critically, these local fixture labels **are not native GENESIS-ELF-001 hatch receipts**. No model inference is performed, and the checker is not an independently running LLM or independently secured process. The card is never published or posted to Abundent, Kinship, or another service.

## First runnable path

```bash
npm test
npm start
```

Open `http://127.0.0.1:7789`, find **House party**, and click **Run the fixture party**. The result says `HOLD_HUMAN_REVIEW` on success; a mismatch yields `REFUSE_DRAFT`. The local history survives a restart.

The fixture preserves:

- explicit synthetic source IDs and accurate amounts/units;
- content bytes and SHA-256 hash;
- two different occurrence labels (no identity or permissions inherited);
- independent deterministic artifact checks;
- `modelInvoked=false`, `originalElfHatchInvoked=false`, `authorizedForPublication=false`;
- `HOLD_HUMAN_REVIEW` rather than any admission, dissemination or resource commitment.

## Native evidence bridge: actual OpenManus model source → two original ELF copies

The source projects already contain an independently verified **STACK² 029** experiment, *on an experimental, unmerged Workbench branch*. It used a real pinned OpenManus ToolCallAgent with Ollama `qwen2.5:3b`, native LOADOUT `OPENMANUS-LIVE-001`, and two independently generated **original** GENESIS-ELF-001 copy hatches, followed by a cold verifier.

The existing experiment does **not** show a model running inside ELF or creating the Garden card. It shows real model **source bytes** flowing through a bounded gate into two mortal ELF copies. That distinction is mandatory.

For an operator who already possesses the exact native source and the original on-disk evidence, `tools/verify-native-029.py` uses the **original Workbench** verifier and **original LOADOUT** verifier. It does not reimplement/guess receipt validation. It requires these exact reviewed pins:

```text
the-static-collective/static-workbench @ 460b3788d01ec068001b5708654c045d2566532a
the-static-collective/LOADOUT        @ dd5456d45946271e2d20d1dc6145b71576d2380b
FoundationAgents/OpenManus           @ 3309bf4e416fb1c74b008f3e86494439a31bad53
```

**Cold recheck on existing evidence only:**

```bash
python3 tools/verify-native-029.py \
  --workbench-root /path/to/original-workbench-at-exact-pin \
  --loadout-root /path/to/LOADOUT-at-exact-pin \
  --live-bundle /tmp/elf-live-evidence/openmanus-live-001.json \
  --live-gate-summary /tmp/elf-live-evidence/elf-live-gate-summary.json \
  --workspace /tmp/elf-live-child \
  --lineage-root /tmp/elf-lineage-029
```

The helper reads original native on-disk evidence. It confirms Workbench/LOADOUT checkout HEADs, invokes the real Workbench `live_source` and `recheck_lineage` functions, and produces only a sanitized digest summary on stdout. **It never starts a model, hatches an ELF, or imports unverified report text into JAR;VIS as trusted state.** An absent local checkout or evidence means HOLD. SHA-256 and local pin checks are not OS sandboxing or human identity proof.

Original experiment: [static-workbench PR #124](https://github.com/the-static-collective/static-workbench/pull/124). Original LOADOUT donor: [LOADOUT PR #18](https://github.com/the-static-collective/LOADOUT/pull/18). Both were experimental/open when this slice was authored; merging JAR;VIS does not merge those donor branches.

### What still separates us from the *full* party

1. An actual operator-approved, runtime-bound LOADOUT compile and capability fence for the particular Garden task rather than the frozen OPENMANUS-LIVE-001 specimen.
2. Real OpenManus output creation using the authorized task and scoped tools.
3. A real authenticated ELF hatch (or independently attributable occurrence) with explicit parentage and lifespan; source model output and ELF producer are never collapsed.
4. A second, separately constituted *actual* review occurrence, not just a deterministic function in the same process.
5. Owner-local consent and admission for any external act, cryptographic receipts when appropriate, and explicit human approval for printing/publication.

## Guardrails

```text
TASK SUGGESTION != AUTHORIZATION
LOADOUT BINDING != EXECUTION PERMISSION
ORIGINAL MODEL OUTPUT != ELF OCCURRENCE
ELF COPY != MODEL-EXECUTED ELF HATCH
DETERMINISTIC REVIEW != INDEPENDENT AGENT
RECEIPT != TRUTH
DRAFT != PRINT AUTHORIZATION
HOLD != PUBLISH
```

JAR;VIS remains the coordinator and return address, not an all-powerful agent that borrows a sibling's credentials or constitutional identity.

**HOUSE PARTY 004 is an honest rehearsal, plus an explicitly cold native evidence handoff. Not yet an authenticated live multi-agent composition.**
